# 單字亂認：整段分類改用雙模型平均

> 2026-11-02｜工具 `scripts/oovbench.py`、`scripts/eval_backend.py`｜數字在 `metrics.json`、`verify.json`

## 結論先講

**整段分類改成 w2000n＋w2000bg 平均機率、門檻維持 0.5：亂認降約四成，正確率不變。** 不用重訓，兩個模型本來就都載入了。代價是低信心影片的相位一致率下降，但使用者看到的高信心結果沒有退步。

| | 單模型 | 雙模型平均 |
| --- | --- | --- |
| WLASL：其他 1900 詞被亂認 | 345/1314＝26%（24～29） | **223/1314＝17%（15～19）** |
| WLASL：100 詞第一個詞正確 | 70/100 | 70/100 |
| WLASL：100 詞沒有輸出 | 23 | 25 |
| YouTube：詞彙表外章節被亂認 | 32/144＝22%（16～30） | **18/144＝12.5%（8～19）** |
| YouTube：第一個詞正確 | 63/88＝72% | 62/88＝70% |
| YouTube：輸出的詞正確（快速影片） | 40/77＝52% | **39/60＝65%** |

## 怎麼選的

單純提高信心門檻也能降亂認，但正確率會一起掉，所以比較方式是**固定誤報率，看誰留下最多正確輸出**。門檻只用 WLASL test 偶數 video_id 的詞彙表外詞來定，驗證看奇數半（100 詞內 60 支）和 YouTube。

誤報目標 15% 時（完整四個目標見 `metrics.json`）：

| 訊號 | 奇數半 正確 | 奇數半 亂認 | YouTube 正確 | YouTube 亂認 | YouTube 輸出正確 |
| --- | --- | --- | --- | --- | --- |
| 現行信心 | 38/60 | 14% | 57/88 | 14% | 59% |
| 2000 類機率 | 40/60 | 17% | 63/88 | 15% | 59% |
| energy | 41/60 | 18% | 60/88 | 13% | 61% |
| 雙模型同意×信心 | 38/60 | 15% | 60/88 | 10% | 69% |
| **雙模型平均（換輸出）** | **43/60** | **16%** | **62/88** | **11%** | **67%** |

- **我原本的假設只對一半**：w2000n 訓練了 2000 類，匯出時丟掉 1900 類的輸出。把它接回來有幫助，但不如雙模型平均。
- 雙模型平均在這個目標的門檻是 0.512，接近現有的 0.5，所以直接沿用 0.5，不多加一個參數。上表第一節是實際後端路徑、門檻 0.5 的結果。

- 驗收標準（22 fps 高信心一致 ≥95%、後端 top-1 ≥71%）**都通過**。
- **整體一致率確實退步**，主要落在低信心的影片。2026-11-03 查明原因並判斷不用改，見 [相位一致率報告](../phase-stability/report.md)。
- 推論多跑一個模型，單次約多 1 毫秒（先前量到 CPU 約 1.2 毫秒），相對 MediaPipe 每幀約 26 毫秒可忽略；這是推估，沒有重新量。

## 其他模式

連續對話的窗口偵測沒有改。不過對話裡短段落還是走整段分類，YouTube 對話的輸出因此從 108 變 101、對中從 4 變 3（精確 3.7%→3.0%，基準 1.1%→0.9%），命中數太少，看不出差別。

## 限制

- **沒有測到真正沒學過的詞**：這 1900 詞和 YouTube 章節裡的詞幾乎都在 w2000n、w2000bg 的訓練詞彙內。詞彙表外的新詞效果可能比較差。
- **YouTube 已經不是完全獨立**：同一批影片看過多種訊號的結果，雖然門檻沒用它定，但選方案時有參考。之後的改版要加新影片才算獨立驗證。
- 100 詞內只有 100 支 test 影片、YouTube 88 章，正確率差 1～2 支都在誤差內；亂認的下降則明顯超出信賴區間（WLASL 區間不重疊）。
- 窗口偵測的亂認沒有處理：教學影片大多走窗口偵測，這條路徑只有 w2000bg 的背景類和 0.7 門檻。

## 怎麼關掉

設環境變數 `WLASL_ENSEMBLE=0` 就回到單模型。
